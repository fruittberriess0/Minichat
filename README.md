# MiniChat ❤️

Личная переписка и общее пространство для двоих. JavaScript, Vite, Supabase Auth / Database / Storage / Realtime и устанавливаемая PWA.

Возможности и границы проверки: [docs/FEATURES.md](docs/FEATURES.md). История версий: [CHANGELOG.md](CHANGELOG.md). Порядок запуска: [docs/ROADMAP.md](docs/ROADMAP.md).

## Локальный запуск

Нужна Node.js 22.12 или новее.

```sh
npm ci
cp .env.example .env.local
# Заполнить публичные реквизиты отдельного Supabase-проекта для разработки.
npm run dev
```

Ненастроенный локальный запуск использует несуществующий адрес minichat-dev.invalid, поэтому случайно не записывает тестовые сообщения в рабочую базу. Никогда не записывайте service_role / secret key в VITE_*: эти значения доступны браузеру.

## База данных

Существующие миграции предполагают исходные таблицы profiles, chats, chat_members и messages. Для пустого dev-проекта сначала выполните supabase/bootstrap-dev.sql. Этот файл откажется перезаписывать существующие таблицы. Затем примените миграции и настройте Supabase Auth и приватный Storage. Тестовая схема в tests/db предназначена только для локальных проверок.

Применять и проверять изменения сначала в отдельном dev-проекте, в порядке имён:

1. 202610240001_messaging_features.sql
2. 202610240002_core_rls_and_rate_limit.sql
3. 202610240003_private_realtime_channels.sql
4. 202610240004_shared_space.sql
5. 202610240005_device_sessions.sql
6. 202610240006_e2ee_text_messages.sql
7. 20261101172729_chat_completion.sql

Публикация кода не применяет SQL к рабочей базе. Новая миграция добавляет подтверждения доставки/чтения, общие заметки, игры, управление видео, поиск и ограничения по сроку хранения. Она добавляет сообщения, реакции и новые таблицы в существующую публикацию supabase_realtime. Миграция 003 включает частные темы chat:<uuid>; в настройках Realtime запретите публичные каналы, если выбран такой режим доступа.

Включите расширение pg_cron до последней миграции, чтобы создать задачу minichat-expiry. Если расширение включено позднее, задачу можно добавить в SQL Editor:

```sql
select cron.schedule('minichat-expiry','* * * * *','select minichat_private.purge_expired()');
```

Истёкшие сообщения скрываются по таймеру в интерфейсе и через RLS сразу, физическое удаление строк выполняется раз в минуту. Вложения Storage и резервные копии этим заданием не удаляются.

## Vercel и ветка dev

Production остаётся в main, изменения проверяются в dev. Для Git-превью укажите отдельные Preview-переменные Supabase и разрешённый URL перенаправления Auth. Сборка Preview останавливается, если реквизиты отсутствуют или указывают на известную рабочую базу. Production сохраняет совместимость с прежними публичными реквизитами, но предпочтительны явные переменные окружения.

Сборка: npm run build, публикуемая папка: dist. Vite формирует список файлов офлайн-оболочки PWA при каждой сборке. CI ветки dev проверяет исходники, модули, PostgreSQL, браузерные сценарии и сборку.

## Push, устройства и YouTube

Настройка Web Push описана в [supabase/functions/README.md](supabase/functions/README.md). Нужны VAPID, функция push-notify, секрет webhook и webhook INSERT messages. Для iOS требуется поддерживаемая версия Safari и установленная PWA. Получение push не означает доставку самого сообщения: статус доставки появляется после его получения клиентом.

В общем пространстве оба участника открывают карточку YouTube. Общие кнопки управляют воспроизведением, паузой и переходом к секунде. Браузер может потребовать нажатие ▶, а автор ролика может запретить встраивание.

## Проверки

```sh
npm test           # исходники, модули, одноразовая PostgreSQL
npx playwright install chromium
npm run test:e2e   # браузер с тестовыми ответами API
npm run build
```

Если тестовый Chromium не поддерживает систему, можно указать PLAYWRIGHT_CHROMIUM_EXECUTABLE с абсолютным путём к установленному Chrome.

Автоматические проверки не обращаются к личной переписке. Для выпуска остаётся проверка двух реальных пользователей, закрытой PWA, Storage, Realtime и push на dev-проекте.

## Структура

- index.html — разметка приложения.
- src/style.css — оформление и мобильная компоновка.
- src/main.js — основные действия приложения.
- src/features/ — общие занятия, очередь, статусы, экспорт и вспомогательная логика.
- public/ — manifest, иконки и шаблон service worker.
- supabase/ — миграции и серверные функции.
- tests/ — проверки логики, базы и браузера.

Экспериментальное E2EE относится только к новым текстовым сообщениям; оно не проходило независимый аудит и не шифрует вложения или метаданные. Для старых сообщений нужны исходные ключи устройства. Черновики, свои обои и очередь хранятся на устройстве; очистка данных браузера удалит их.
