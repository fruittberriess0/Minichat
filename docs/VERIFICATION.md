Браузерный сценарий очереди покрывает ошибку отправки, перезагрузку страницы, принятый сервером INSERT с потерянным ответом и повтор без второго сообщения. PostgreSQL проверяет доставку и чтение, стабильность отметок времени, счётчики, чужие ходы, устаревшую версию игры, закрытое загаданное слово, общие заметки, управление просмотром, поиск и недоступность просроченных сообщений.

Проверки API браузера используют тестовые ответы. Проверки SQL выполняются через PGlite на базовой схеме и всех миграциях. Supabase Auth, Storage, Realtime и push на реальных устройствах требуют отдельного dev-проекта и дополнительной проверки после его настройки.

## Что обнаружено в подключённом окружении

У действующего Supabase-проекта есть исходные таблицы, но нет истории применённых миграций из репозитория. Схема изучена без чтения содержимого переписки. В рабочую базу SQL не отправлялся.

Проверка Supabase указала на доступ anon к старым SECURITY DEFINER-функциям. Подготовленные миграции отзывают эти права; это ещё не изменение действующего сервера. [Описание проверки прав на функции](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable).

Отдельный dev-проект пока не подключён. Vercel вернул 403 при обращении к команде существующего проекта и требует подтвердить доступ текущего подключения. Превью и серверная часть новых функций ещё не опубликованы.

## Проверка развёрнутого minichat-dev

Подключён отдельный бесплатный Supabase-проект minichat-dev в eu-west-2. На нём установлены миграции, приватный Storage, серверные уведомления и задача очистки просроченных строк. Preview ветки dev успешно собирается в Vercel.

Восемь проверок настоящего API подтвердили доставку через частный Realtime, подтверждения доставки/чтения, отказ постороннему, редактирование и реакции, общие заметки и опросы, поочерёдные ходы, приватные файлы, поиск и аутентификацию push-webhook. Сервер уведомлений проверен без зарегистрированных устройств: получение уведомления на физическом телефоне требует разрешения владельца устройства.

Девять сценариев в двух отдельных браузерных сеансах проверили вход, сообщения и прочтение, цитаты и реакции, редактирование, общий таймер, загрузку файла, запись голосового через тестовый микрофон, экспорт всей переписки и мобильную компоновку. Ошибок страницы нет.

Временная серверная функция, создавшая три тестовых аккаунта, закрыта и отвечает 410. Пароли и приватные push-ключи не входят в репозиторий. Ключи уведомлений хранятся в Vault, браузеру доступна только публичная часть.

Новый Supabase-проект пока перенаправляет ссылки входа на localhost:3000. Для Magic Link и восстановления пароля нужно сохранить Site URL и Redirect URLs в настройках Auth; подключённые инструменты не предоставляют изменение этой настройки. Рабочая база ещё не обновлена.
